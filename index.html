Help, limits, and moving to another computer

Read this before treating the workstation as the main system.

What this is

A browser-based documentation tool for structured scan reports. Its core runs from a single HTML file using local HTML, CSS, and JavaScript. The file also references an optional Tailwind browser CDN script; the report workflow does not use it and still works offline. Do not treat a remote script as safe for real patient data without a security review.

What to know before use

  • Not a diagnostic or AI interpretation system.
  • It is just hospital recording system.
  • Not multi-computer shared storage. Each browser profile has its own data.
  • Not protection against someone who can open the browser or copy local files.
  • Create different account for different users before entering patient data.

How to Transfer and Set Up the Application on Another Computer

  1. On the development computer, sign in and open Backup / restore.
  2. Export scan-report-backup.json.
  3. Copy index.html and the JSON backup to the target computer. Use relative files only — never a path like C:\Users\… inside the app.
  4. On the target computer, open index.html in Chrome or Edge (double-click or File → Open).
  5. Sign in with a default account if the target has empty storage, then import the backup (Replace if this is the new main system).
  6. Verify user list, a known report, search, edit, and print. Then change default passwords.

Success means both the application files and restored data work. Opening the HTML file alone is not a completed migration.

On the first open after this credential update, passwords in an existing browser profile are reset once and its session is signed out. Importing an older backup also resets passwords for the imported accounts. Set unique account passwords in Users before handling real patient data.

Browser notes

Data lives in localStorage in a particular browser profile. For local file:// pages, browser storage behavior can vary by browser and file path. A different browser, profile, or computer will not automatically receive template changes. Clearing site data deletes reports. Private/Incognito windows forget data when closed. Export backups rather than relying on file paths.

Medical safety

Predefined findings are labeled demonstration text. The reporting professional must review every report before it is issued.

Review and print

After entering the impression, the Preview step shows the report on its letterhead. Actions below the report let you return to the form, save a draft, finalize, or open the browser's Print / Save as PDF dialog. On A5, patient details are paired left and right, findings run in two columns, and the impression stays full-width for readability. Select A5 paper, 100% scale, and turn off browser headers and footers in the print dialog. Longer reports may span multiple A5 pages. Printing alone does not save the report.

Presentation illustrations

From Scan templates, an administrator can install the presentation illustration pack while online. In Chrome or Edge, choose the folder containing this application file. The installer downloads public-domain historical illustrations and writes PNG copies in img/. If folder access is unavailable, use the individual download buttons and move those PNGs into img/. When Cephalic, Cephalic_OPP, Unstable, Breech or Transverse is selected in an obstetric report, its local reference image appears immediately, in the preview, and in print. The app's Print / Save PDF button stops if that image is missing.img/ with index.html; a JSON backup does not include the PNG files. See img/README.md for sources and reuse information.

Editing report templates

Administrators can open Scan templates, choose Edit form, and add, edit, or remove sections, fields, choices, and measurements. Add a measurement inside any section and choose its position, including between fields. Legacy standalone measurements are placed in a first Measurements section when that template is saved; until then they display first in new report forms. Apply each item, then choose Save template to publish it. New reports in this browser profile use the saved version. Historical reports and forms already in progress keep their snapshot; other computers need an exported and imported JSON backup. Always transfer the updated application file too; older versions cannot render section measurements. To publish changed templates or patient/report fields to a different computer, export its data first and use Replace: Merge does not overwrite existing configurations.

The New report workflow begins with Examination, followed by Patient. Each scan template can define extra patient fields. For Obstetric Ultrasound, Sex is fixed to Female on the patient form and blank LMP (date) and Parity (text) fields are shown. This is a form rule, not verification of a patient's sex or a clinical conclusion. Older saved reports retain their original details; verify discrepancies before saving an edited report.

Patient and other report entries

Under Report fields, administrators can add, rename, change, require, and remove optional patient, examination and conclusion fields. Patient name, card number, examination date and impression cannot be removed because reports need them. Saved reports retain their own field definitions. Under Patient entries, an administrator can edit any active report's patient details, restore an archived report to a draft, or permanently delete an archived report and its patient data. Patient information is stored per report, not in a shared patient registry. Export a backup before irreversible deletions. Version 1 and 2 JSON backups are upgraded to the current format on import.
